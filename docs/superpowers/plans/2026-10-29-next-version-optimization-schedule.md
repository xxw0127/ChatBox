# ChatBox 下一版本优化日程

日期：2026-10-29
当前版本：0.4.1（已上线）

## 0.4.2 — 体验补丁（10/30–11/1）

优先处理这轮暴露出来、成本低但影响直接的问题：

1. **搜索与右上角“更多”**
   - 聊天标题右侧保留放大镜快捷入口，同时新增“更多”菜单按钮（三点），和右侧栏开关并列；`Ctrl+F` 继续保留。
   - “更多”菜单包含：`查找聊天内容`、`文件管理`、`群设置`（群主/管理员可见）。
   - 群设置从右侧栏标题的齿轮/三条杠移到“更多”菜单；文件管理以“更多”菜单为主入口，右侧栏底部按钮实施时去重（保留一个入口即可）。
   - 未选择会话时菜单项置灰；群设置按当前群角色显示。
   - **右侧栏搜索**
     - 群聊顶部搜索框改成 `搜索成员`，本地过滤右侧成员列表，不再触发消息搜索。
     - 私聊搜索框从右侧栏底部移到顶部，继续用 `搜索消息`，回车走现有 `startPanelSearch`。
     - 两个搜索框都加空结果提示，避免用户以为没反应。
   - 测试：群聊成员过滤、私聊顶部消息搜索、More 菜单动作和角色可见性、文件管理入口、`Ctrl+F` 和放大镜仍生效。
2. **群未读角标**
   - 未读数从群名标题里移出，改成独立小角标，不占标题文字。
3. **缩略图缓存失效**
   - 缓存 key 加版本；旧的 320×180 缩略图自动删除并重新拉取 640px 版本。
   - 解决其他机器仍看到旧糊图的问题。
4. **更新证书兜底**
   - CA 证书嵌入 qrc；`certs/ca.crt` 缺失时使用内置证书。
   - 更新失败日志记录版本、证书路径和 Qt TLS 状态，便于定位。
5. **更新弹窗文字裁切**
   - 现象：“发现新版本”弹窗的标题、正文和按钮文字上下像被切掉一截。
   - 重点排查：全局 QSS 的 `font-family: "Segoe UI", "Microsoft YaHei UI"` 中文 fallback 度量；`AA_EnableHighDpiScaling` + `PassThrough` 在 125%/150% 下的取整；QLabel 固定高度/内边距。
   - 修复方向：字体族把 `Microsoft YaHei UI` 放首位或给弹窗显式字体；QLabel 最小高度按 `fontMetrics` 计算；按钮补 `min-height`/上下 padding；100%/125%/150% 三档截图验收。
   - 顺手清理 `QLabel#AccountMenuHint` 遗留的 18px 字体和 `padding-right: 4px`，避免新的 16px 三条杠被裁。
6. **关闭到托盘**
   - 默认点击窗口 X 不退出程序，隐藏到系统托盘继续收消息。
   - 设置里增加“关闭主窗口时”选项：`最小化到托盘` / `退出程序`。
   - 托盘菜单“退出”始终是真正退出，不受该设置影响。
   - 没有系统托盘时 X 仍然退出，避免变成不可见后台进程。
   - 开机自启 `--minimized` 与这个设置兼容；隐藏时可选一次托盘气泡提示“仍在后台运行”。
   - 测试：默认隐藏、改设置后退出、无托盘退出、托盘“退出”真正退出。
7. **群聊昵称与资料页入口**
   - 群聊消息气泡的发送者只显示昵称，不再显示 `U00000007` 这类 ID；ID 保留在资料页/右侧栏。
   - 头像和昵称都加 `profile-open:///<user_id>` 链接，点击直接打开对应用户资料页。
   - 自己的头像/昵称打开自己的资料页；离线时走现有“当前离线，无法查看资料”提示。
   - 不影响消息右键菜单、回复/撤回等已有交互。
   - 测试：渲染结果不含发送者 ID、头像和昵称都有 profile 链接、`anchorClicked` 识别 `profile-open`、自己的消息走 `openOwnProfile`。
8. **通知中心整合（好友申请 + 群邀请）**
   - 现状：群邀请服务端已经持久化在 `room_invites`，登录/恢复时也会拉取；但入口只在“群组”页的群通知里，未读时用户容易完全错过，且必须先选中条目才能点接受。
   - 目标：在“会话”页做一个统一的“通知”入口，合并好友申请 + 群邀请，共用一个未读角标。
   - 通知列表按类型分组：好友申请、群邀请；每条直接显示 `接受` / `拒绝` 按钮，不需要先选中。
   - 离线用户登录/恢复后拉取未处理邀请，角标可见；可选再加一条托盘提示“你有 N 条待处理通知”。
   - 在线收到邀请时更新通知中心，不再只依赖一次性弹窗。
   - 群管理员的“入群申请”先保留在群通知/群设置里；如果时间允许再并入同一入口。
   - 端到端测试：离线期间收到邀请 → 登录后角标出现 → 直接点接受/拒绝 → 群成员关系/邀请状态正确更新。
9. **连续消息气泡间距**
   - 同一个发送者连续发消息时，后续气泡与上一条的视觉间距再收紧。
   - 现状：续条 `margin-top: 4px` + 外层表格 `cellpadding=4`，实际间隙看起来仍偏大。
   - 目标：续条间距降到约 2–4px，第一条仍保留正常的组间距和头像对齐。
   - 实现方向：续条 top margin 改成 0–1px；续条外层气泡 padding 从 4 降到 2 或只保留左右 padding；不要影响圆角、右键菜单和头像列对齐。
   - 测试：渲染同一发送者 3 条消息，用 `messageBubbleRect` 量相邻气泡 gap，续条 gap ≤ 6px，首条组间距保持。
10. **高 DPI / 深色主题**
   - 125%/150% 缩放下检查新图标、按钮、标题和右侧栏宽度。
   - 深色主题下三条杠、侧栏状态图标、未读角标对比度检查。
11. **生产构建树修复**
   - 当前生产 `/home/ubuntu/chatbox` 源码树缺 `server/file`，这次是临时用完整源码构建的。
   - 部署改为从仓库完整源码构建，避免再次出现“构建产物少模块”的风险。

验收：客户端测试全绿；干净 Windows 机器验证 TLS、文件传输、更新；0.4.2 包、feed、回滚备份齐全。

## 0.5.0 — 多设备与 Android 底座（11/1–11/7）

验收：任务测试 + 双设备联调 + 旧客户端回归 + 服务端部署/回滚演练。

### 0.5.0 公告功能（与多设备同版，预计 2–3 天）

**群公告**

- 群主/管理员可发布、编辑、删除；普通成员只读。
- 服务端按群角色校验，不能只靠客户端隐藏按钮。
- 展示位置：群设置/右侧栏“群公告”卡片 + 群聊顶部可折叠横幅（未读时高亮）。
- 记录发布者、发布时间、最后编辑时间；群解散/成员退出时按规则清理。
- 需要决定：只保留最新一条，还是保留历史列表（建议先做“最新一条 + 历史可展开”）。

**系统公告**

- 仅运维发布，全局所有用户可见；普通客户端账号没有发布权限。
- 入口：登录后顶部横幅 + 公告中心；支持已读/未读、忽略、过期时间、优先级。
- 建议发布方式：服务器端管理命令/脚本（如 `chatbox_announce`），不把管理员权限放进普通客户端。
- 旧 0.4.x 客户端收到未知命令必须忽略，不能断线；新客户端登录时拉取未读系统公告。

**服务端与协议**

- `announcements`（scope、group_id、title、content、publisher、时间、过期、优先级、状态）。
- `announcement_reads`（user_id、announcement_id、read_at）。
- 命令：列表/拉取/发布/编辑/删除/标记已读；增量同步按游标。
- 全部预处理语句；群公告权限在 worker 层校验；系统公告走独立管理凭据。

**客户端**

- 群设置/右侧栏公告编辑入口（仅群主/管理员可见）。
- 系统公告横幅/公告中心、未读角标、已读上报。
- 长文本滚动、换行、链接/复制；空状态和错误状态。

**已确认（2026-10-29）**

1. 系统公告走**服务器端管理命令**，不做客户端隐藏管理员入口。
   - 命令建议：`chatbox_announce --title ... --content ... [--expires ...] [--priority ...] [--list] [--revoke <id>]`
   - 认证边界是服务器 shell 权限（SSH + sudo/ubuntu 用户），命令读取 `conf/chatbox.env` 的数据库配置。
   - 发布/撤销写审计日志，记录操作者、时间、标题、公告 ID。
2. 群公告同时显示在右侧栏“群公告”卡片和群聊顶部可折叠横幅。
3. 群公告保留“最新一条 + 历史可展开”，历史默认折叠。

**公告功能任务拆分（0.5.0）**

1. 服务端表与迁移：`announcements`、`announcement_reads`，可重复执行。
2. 协议命令：列表/拉取/发布/编辑/删除/标记已读，全部追加式。
3. 服务端服务层：群角色校验、系统公告独立管理入口、fan-out、离线同步。
4. `chatbox_announce` 管理命令：发布/列表/撤销、审计日志。
5. 客户端群公告：编辑对话框、右侧栏卡片、顶部横幅、历史展开。
6. 客户端系统公告：登录拉取、顶部横幅、公告中心、已读/忽略/过期。
7. 测试：权限矩阵、旧客户端忽略未知推送、双设备已读同步、长文本/空状态。

## 风险与顺序

- 0.4.2 通知中心整合如果比预期大（尤其并入管理员入群申请），优先保证好友申请 + 群邀请，入群申请留到 0.5.1；0.4.2 最晚顺延到 11/1。
- 0.5.0 多设备 + 公告一起做，工作量大；如果公告阻塞，优先保证多设备底座，公告顺延到 0.5.1，但不单独拆版本发布。
- 0.3.2 旧客户端无法自助更新，只能手动装 0.4.x；0.4.2 的 CA 兜底和文档用于降低再次发生的概率。
- 0.4.2 的生产构建树修复要放在发布前，否则下一次部署仍有缺模块风险。
