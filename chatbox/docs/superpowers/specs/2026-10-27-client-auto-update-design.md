# ChatBox 客户端自动更新设计

日期：2026-10-27

## 目标

- 客户端启动后自动检查新版本；有更新时提示用户。
- 用户点“立即更新”后自动下载、校验、替换当前便携目录并重启。
- 更新源固定为自有服务器，不再让用户手填服务器 IP、端口或 TLS。
- 更新失败时保留旧版本可继续使用，不出现“更新后打不开、旧版也没了”。

## 已确定的产品决定

- 更新检查在客户端启动后自动执行，不阻塞登录和主界面。
- 更新包和版本清单放在 `https://121.5.168.189/updates/`，使用 443。
- 登录页和设置页不再提供服务器地址、端口、TLS 编辑；客户端固定连接 `121.5.168.189:9443`。
- 旧版设置中的 `frp-oil.com:15318` 继续自动迁移到新地址；其他自定义 `server/*` 也不再作为运行时入口，统一回到固定地址。
- 只有 Windows 10/11 便携版支持一键替换；其他平台仅提示手动下载。
- 更新是“提示后点击更新”，不做静默强制安装。
- 第一个带更新器的版本（0.2.4）需要手动安装一次；从它开始后续版本才能一键更新。
- 更新助手只使用 Windows 自带的 PowerShell 5.1；检测不到 PowerShell、`tar.exe` 或目录可写时，降级为“打开下载页/手动更新”，不假装一键成功。

## 构建/测试地址覆盖

生产包的服务器地址和更新清单地址是固定常量。开发者/验收如果需要连临时服务器，只能通过**构建期 qmake define** 覆盖，不进入正常发布包：

```text
CHATBOX_SERVER_HOST
CHATBOX_SERVER_PORT
CHATBOX_UPDATE_MANIFEST
```

这样不会重新把 IP/端口输入框带回用户界面，也不会让用户通过配置文件绕过服务器固定地址。

## 更新清单

服务器文件：

```text
https://121.5.168.189/updates/latest.json
https://121.5.168.189/updates/chatbox-<version>-win64.zip
```

`latest.json`：

```json
{
  "schema": 1,
  "version": "0.2.4",
  "url": "https://121.5.168.189/updates/chatbox-0.2.4-win64.zip",
  "sha256": "<zip sha256>",
  "notes": "更新说明",
  "published_at": "2026-10-27T12:00:00Z"
}
```

约束：

- 清单大小上限 64 KiB；只接受 `121.5.168.189` 的 HTTPS URL。
- 版本使用 `QVersionNumber` 比较，低于或等于当前版本不提示。
- 下载后用 `QCryptographicHash` 校验 `sha256`；不匹配就删除临时文件并报错。
- TLS 使用包内 `certs/ca.crt` 校验，不关闭证书校验。

## 启动检查流程

1. 主窗口显示后延迟约 1.5 秒发起清单请求，避免和登录/首屏竞争。
2. 请求失败、离线、证书错误：静默记录日志，不打扰用户。
3. 发现新版本：显示非模态更新提示，包含版本、更新说明和“立即更新 / 稍后”。
4. 用户选择“稍后”：本次启动不再提示；下次启动重新检查。
5. 用户选择“立即更新”：显示下载进度，期间可以取消。
6. 下载完成并校验成功后，启动更新助手，关闭客户端。
7. 更新助手等待原进程退出，备份旧目录，替换文件，启动新版本；失败则恢复旧目录并启动旧版本。

## 更新助手

使用应用自己生成并写入 `%TEMP%\ChatBox\update\` 的 PowerShell 更新脚本，不从更新 ZIP 里执行脚本。脚本参数：

```text
-ProcessId <pid>
-SourceDir <解压后的新版本目录>
-TargetDir <当前安装目录>
-Executable <target\chatbox.exe>
```

步骤：

1. `Wait-Process` 等待当前进程退出。
2. 将当前安装目录复制到 `%TEMP%\ChatBox\backup-<timestamp>`，并写入 `update-in-progress` 标记。
3. 复制新目录内容覆盖安装目录；发布包就是完整便携目录，按镜像方式删除旧包中已不存在的文件，避免残留旧 DLL。
4. 启动新 `chatbox.exe`，等待 5 秒确认进程仍在运行。
5. 健康检查通过：删除备份和标记，退出。
6. 健康检查失败或复制失败：从备份恢复，启动旧 `chatbox.exe`，保留失败原因到 `%TEMP%\ChatBox\update-result.txt`；客户端下次启动读取并提示一次。

安全约束：

- 下载 ZIP 在临时目录解压，禁止把清单里的路径拼进 PowerShell 命令。
- 更新脚本使用固定模板和参数，不执行 ZIP 内的脚本。
- 安装目录整体纳入备份；用户的 `%APPDATA%` 数据和本机历史不在安装目录，不随更新替换。
- 目标目录不可写时立即报错，提示用户把客户端放到可写目录或手动下载，不尝试提权。
- 更新器不跟随清单里的任意 URL；域名必须是 `121.5.168.189` 且 scheme 为 HTTPS。
- 更新脚本在复制前检查更新 ZIP 中至少包含 `chatbox.exe`、`Qt5Sql.dll`、`sqldrivers\\qsqlite.dll`，否则不执行替换。

## 删除服务器配置入口

- `LoginPage`：删除服务器、端口、TLS 和右上角 `⋯` 高级服务器面板；保留“自动登录 / 记住密码”和注册流程。
- `SettingsDialog`：删除服务器/端口/TLS 表单，改为只读显示当前固定服务器地址。
- `MainWindow`：登录、注册、切换账号都使用 `client_config.h` 的固定常量，不再接受 UI 传入的 host/port/tls。
- 旧 QSettings 中的 `server/*` 只用于迁移和兼容，不再暴露给用户。

## 服务端发布入口

- nginx 增加 HTTPS 443 静态更新站点，根目录 `/var/www/chatbox-updates`。
- 复用当前 `121.5.168.189` 证书；只允许 GET/HEAD。
- UFW 和腾讯云安全组放行 443；现有 9443 继续用于客户端长连接。
- 发布脚本生成清单、计算 SHA256、上传 ZIP 和 JSON，并在客户端发布包构建完成后执行。
- `latest.json` 只有一套生产 feed；首次真实验收使用 0.2.4 作为“第一版更新器”，随后发布 0.2.5 做真实升级，且验收期间没有正式用户依赖自动更新。若需要 beta，再增加 `/updates/beta/latest.json` 和构建期 URL 覆盖。

## 测试与验收

- 版本比较：低版本/同版本/高版本。
- 清单解析：缺字段、非法 URL、过大清单、非法版本。
- SHA256 不匹配时必须中止且不启动更新助手。
- 下载取消和网络失败不能影响当前客户端。
- 启动检查只在有更新时显示提示；稍后不再重复提示。
- 更新助手源/目标路径包含空格时仍能工作。
- 更新后启动 5 秒健康检查失败时自动回滚并重启旧版。
- 旧服务器配置迁移测试保持通过。
- 登录页/设置页不再出现服务器编辑控件。
- 真实发布包一次完整更新：旧版 → 新版，用户数据目录保持不变。
- 首次升级演练：手动安装 0.2.4，再用 0.2.5 验证启动提示、下载、校验、替换和重启。

## 非目标

- 增量更新（delta patch）。
- Linux/macOS 自动替换。
- 强制更新/静默更新。
- Windows Authenticode 代码签名；更新包校验采用 TLS 固定 CA + SHA256。

## 发布顺序

1. 客户端实现更新检查和替换助手。
2. 服务端配置 443 更新站点并生成测试清单。
3. 构建两个连续测试版本，完成一次真实更新演练。
4. 发布新版本并更新更新清单。
5. 观察启动检查、失败回滚和旧配置迁移。
